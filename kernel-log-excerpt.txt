In the failing cases the firmware programs 02:01.0 and the Arc's own bridges for the BAR above
4 GiB, but leaves the CPU root port 00:01.2 and the chipset upstream port 01:00.0 forwarding only
0xfc400000-0xfccfffff. CPU writes to the framebuffer therefore never reach the card during POST.
Linux detects this and rebuilds the chain, so the operating system is unaffected.

BIOS P5.82 shows the same pattern (Above 4G on: "can't claim", noise at POST).
